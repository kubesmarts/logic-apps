= Getting Started with Data Index
:page-aliases:

This guide walks you through deploying Data Index and verifying it works.

== Prerequisites

Before you begin, ensure you have:

* Kubernetes cluster running (or KIND for local development)
* `kubectl` configured to access your cluster
* `git`, `curl` and `jq` installed
* Java 17+ and Maven (to build the project)

== Get the Source

Clone the repository.
All commands in this guide run from the repository root unless stated otherwise.

[source,bash]
----
git clone https://github.com/kubesmarts/logic-apps.git
cd logic-apps
----

== Quick Start (Development Mode)

The fastest way to start Data Index locally without Kubernetes.

Build the project:

[source,bash]
----
mvn clean install -DskipTests
----

=== PostgreSQL Backend

[source,bash]
----
cd data-index/data-index-service/data-index-service-postgresql
mvn quarkus:dev
----

**What happens:**

* Quarkus Dev Services auto-starts PostgreSQL container
* Flyway runs schema migrations automatically
* Service starts at http://localhost:8080
* GraphQL UI available at http://localhost:8080/q/graphql-ui

=== Elasticsearch Backend

[source,bash]
----
cd data-index/data-index-service/data-index-service-elasticsearch
mvn quarkus:dev
----

**What happens:**

* Quarkus Dev Services auto-starts Elasticsearch container
* Schema initialization (ILM, templates, transforms) runs automatically
* Service starts at http://localhost:8080
* GraphQL UI available at http://localhost:8080/q/graphql-ui
* Elasticsearch available at http://localhost:9200

NOTE: Development mode doesn't include the Vector log collector.
To test with real workflow events, use the KIND installation below.

== Quick Install (KIND)`

Data Index supports two storage backends. Choose one based on your needs:

* **PostgreSQL (MODE 1)** - Recommended for most users, simpler deployment
* **Elasticsearch (MODE 2)** - For high throughput or full-text search requirements
* **Kafka (MODE 3)** - For stream-based ingestion, requires Kafka infrastructure

Each mode has a single script that sets up everything on a local KIND cluster.
Besides `kubectl`, the scripts need `kind`, `docker` and `helm`.

Each script:

. Deletes the KIND cluster named `data-index-test` if it exists, then creates a new one
. Builds the project and the container images, and loads them into the cluster
. Installs the Helm chart with the values for that mode, including a test workflow app
. Runs the E2E tests against the deployment

[NOTE]
====
The scripts also run the E2E tests, so they take a few minutes.
The cluster is kept afterwards, and the GraphQL API is available at http://localhost:30080/graphql.
====

Set `CLUSTER_NAME` to use a different cluster name.

To get a cluster with data without waiting for the E2E tests, run each test workflow `N` times after the deploy and skip the tests:

[source,bash]
----
RUN_WORKFLOWS=3 SKIP_TESTS=true bash data-index/scripts/e2e/full-test-mode1.sh
----

To generate more data later on a running cluster, run `bash data-index/scripts/e2e/run-workflows.sh <N>`.

=== Option 1: PostgreSQL Backend (Recommended)

[source,bash]
----
bash data-index/scripts/e2e/full-test-mode1.sh
----

=== Option 2: Elasticsearch Backend

[source,bash]
----
bash data-index/scripts/e2e/full-test-mode2.sh
----

=== Option 3: Kafka Ingestion

[source,bash]
----
bash data-index/scripts/e2e/full-test-mode3.sh
----

=== Cleanup

[source,bash]
----
kind delete cluster --name data-index-test
----

== Verify Installation

=== Check Pods

All components should be running:

[source,bash]
----
# Data Index service
kubectl get pods -n data-index

# Vector (log collector: Option 1 and Option 2)
kubectl get pods -n logging -l app=vector

# PostgreSQL (Option 1 and Option 3)
kubectl get pods -n postgresql

# Elasticsearch (Option 2)
kubectl get pods -n elasticsearch

# Kafka (Option 3)
kubectl get pods -n kafka
----

Expected output for Option 1:

[source,text]
----
NAMESPACE     NAME                                  READY   STATUS
data-index    data-index-service-xxx                1/1     Running
logging       vector-xxx                             1/1     Running
postgresql    postgresql-0                          1/1     Running
----

=== Test GraphQL API

Query the API to verify it's responding:

[source,bash]
----
# Port-forward to Data Index service
kubectl port-forward -n data-index svc/data-index-service 8080:8080 &

# Query GraphQL
curl -s http://localhost:8080/graphql \
  -H "Content-Type: application/json" \
  -d '{"query":"{ getWorkflowInstances { id name status } }"}' \
  | jq .
----

Expected response (may be empty if no workflows executed yet):

[source,json]
----
{
  "data": {
    "getWorkflowInstances": []
  }
}
----

=== Access GraphQL UI

Open the interactive GraphQL playground in your browser:

[source,bash]
----
# Port-forward to Data Index service (if not already running)
kubectl port-forward -n data-index svc/data-index-service 8080:8080 &

# Open GraphQL UI in browser
open http://localhost:8080/q/graphql-ui/
----

The GraphQL UI provides:

* **Interactive query builder** - Autocomplete and syntax highlighting
* **Schema explorer** - Browse available queries and types
* **Query history** - Saved queries for reuse
* **Documentation** - Inline field descriptions

TIP: Use `Ctrl+Space` in the query editor for autocomplete suggestions.

----

  env PGPASSWORD=dataindex123 \
  psql -U dataindex -d dataindex \
