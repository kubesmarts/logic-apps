= Connect to Elasticsearch
:page-aliases:

Run the `-elasticsearch` image against an existing Elasticsearch cluster.

== Set the connection

[source,bash,subs="attributes+"]
----
docker run -d --name data-index -p 8080:8080 \
  -e ELASTICSEARCH_HOST=es.example.com \
  -e ELASTICSEARCH_PORT=9200 \
  -e ELASTICSEARCH_PROTOCOL=https \
  -e ELASTICSEARCH_USERNAME=elastic \
  -e ELASTICSEARCH_PASSWORD=secret \
  quay.io/kubesmarts/logic-data-index:{image-version}-elasticsearch
----

`ELASTICSEARCH_PROTOCOL` defaults to `http`.
Username and password are optional.

== Let Data Index create the schema

On startup the service creates the ILM policy, ingest pipeline, index templates and transforms if they are missing, then starts the transforms.
The user needs permission to manage those resources.

Tune the transforms with:

[cols="2,1,3"]
|===
|Variable |Default |Effect

|`LOGIC_APPS_DATA_INDEX_TRANSFORM_SMART_FILTER_TIME_WINDOW`
|`1h`
|Events older than this are only reprocessed for instances that are not finished.

|`LOGIC_APPS_DATA_INDEX_ILM_RAW_EVENTS_RETENTION`
|`30d`
|How long raw events are kept. Must be longer than the time window.

|`DATA_INDEX_TRANSFORM_SYNC_DELAY`
|`5s`
|How far the transform checkpoint trails ingestion. Must cover the index refresh interval.
|===

== Manage the schema yourself

If another tool owns the Elasticsearch resources, turn startup initialization off with `LOGIC_APPS_DATA_INDEX_STORAGE_SKIP_INIT_SCHEMA=true` and apply them before the first raw event is written.
The resource files are in the `data-index-storage-elasticsearch-schema` module:

[source,bash]
----
ES=https://elastic:secret@es.example.com:9200
SCHEMA=data-index/data-index-storage/data-index-storage-elasticsearch-schema/src/main/resources/elasticsearch

# 1. ILM policy
sed -e 's/{RETENTION_PERIOD}/30d/g' $SCHEMA/ilm/data-index-events-retention.json \
  | curl -X PUT $ES/_ilm/policy/data-index-events-retention -H 'Content-Type: application/json' -d @-

# 2. Ingest pipeline (must exist before raw events are indexed)
curl -X PUT $ES/_ingest/pipeline/data-index-ingest-timestamp -H 'Content-Type: application/json' \
  -d @$SCHEMA/ingest-pipelines/data-index-ingest-timestamp.json

# 3. Index templates
for t in workflow-events task-events workflow-instances task-executions; do
  curl -X PUT $ES/_index_template/$t -H 'Content-Type: application/json' -d @$SCHEMA/index-templates/$t.json
done

# 4. Transforms
for t in workflow-instances-transform task-executions-transform; do
  sed -e 's/{TIME_WINDOW}/1h/g' -e 's/{SYNC_DELAY}/5s/g' $SCHEMA/transforms/$t.json \
    | curl -X PUT $ES/_transform/$t -H 'Content-Type: application/json' -d @-
  curl -X POST $ES/_transform/$t/_start
done
----

== Check it works

[source,bash]
----
curl -s http://localhost:8080/q/health/ready
curl -s "$ES/_cat/transforms?v"
----

Both transforms should be `started`.
