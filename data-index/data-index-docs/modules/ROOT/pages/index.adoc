== What is Data Index?

Data Index is a *query service* for Open Workflow 1.0.0 runtime execution data.
It reads workflow and task lifecycle events from supported data sources and exposes them through a single GraphQL API for querying workflow instances and task executions from Quarkus Flow applications.

[sidebar]
****
*Key Features:*

* 📊 **GraphQL API** - Query workflow instances and task executions
* 🚀 **Near Real-time** - Events become queryable about 1s after they reach the data source
* 🔍 **Flexible Filtering** - Filter by status, name, namespace, time ranges
* 🎯 **Production Ready** - Every supported data source is fully tested
* 🔄 **Multiple Data Sources** - Same GraphQL API regardless of the data source
****

== How It Works

Data Index reads raw lifecycle events from a data source,
normalizes them into workflow instances and task executions, and serves them through GraphQL.

[NOTE]
====
Getting the events into the data source is outside Data Index.
====

Two terms are used throughout this documentation:

* *Data source* - where Data Index reads raw lifecycle events from.
* *Storage backend* - where Data Index keeps the normalized data that the GraphQL API queries.

They can be the same system or different ones.
In MODE 3, for example, Kafka is the data source and PostgreSQL is the storage backend.

Example with PostgreSQL (MODE 1):

[source,text]
----
Quarkus Flow App
    ↓ (lifecycle events, delivered by a log collector)
PostgreSQL raw event tables          (data source)
    ↓ (Data Index polls and normalizes)
PostgreSQL normalized tables         (storage backend)
    ↓
GraphQL API
----

Other data sources follow the same idea: Data Index starts from the raw events and owns everything from normalization to the API.

== Storage Backends

Data Index supports two production-ready storage backends:

[cols="1,3,2"]
|===
|Backend |Best For |Status

|**PostgreSQL** (MODE 1)
|Most deployments - ACID transactions, simple operations, <50K workflows/day
|✅ Production Ready

|**Elasticsearch** (MODE 2)
|High throughput (100K+ workflows/day), full-text search, advanced analytics
|✅ Production Ready

|===

**Both backends provide:**

* Same GraphQL API (backend-agnostic queries)
* Same data model (WorkflowInstance, TaskExecution)
* Production-grade reliability and performance

Choose based on your requirements - see xref:architecture/overview.adoc#_decision_matrix[Decision Matrix] for detailed comparison.

== What Data Index Does NOT Do

[WARNING]
====
The Data Index API is *read-only*. It does **NOT**:

* Execute workflows (that's Quarkus Flow's job)
* Modify workflow state
* Provide workflow management operations (start/stop/retry)
====

== System Requirements

**Core:**

* Kubernetes cluster (or KIND for local development)
* Vector 0.54+ (deployed by the Helm chart)
* Quarkus Flow applications with https://docs.quarkiverse.io/quarkus-flow/dev/structured-logging.html[structured logging^] enabled

**Storage backend (choose one):**

* PostgreSQL 13+ (MODE 1)
* Elasticsearch 7.10+ (MODE 2)
