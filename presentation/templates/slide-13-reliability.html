Capacity & Tuning: Reliability

Can we trust PostgreSQL triggers and Elasticsearch transforms?

MODE 1: PostgreSQL Triggers

Aspect Analysis
Atomicity ✅ ACID transaction (raw insert + trigger UPSERT atomic)
Failure Modes ❌ Trigger error = INSERT rollback (event lost until replay)
Monitoring ⚠️ No built-in metrics (need custom function + cron)
Testing ✅ Integration tests verify trigger logic
Lag ✅ None (< 1ms synchronous)
Recovery ✅ FluentBit retry on INSERT failure

Mitigation: Comprehensive integration tests + schema migration validation

MODE 2: Elasticsearch Transforms

Aspect Analysis
Atomicity ⚠️ Eventual consistency (raw insert succeeds, transform async)
Failure Modes ✅ Transform error = retry automatically (exponential backoff)
Monitoring ✅ Transform Stats API + Prometheus metrics
Testing ✅ Integration tests with 2s wait for transform
Lag ⚠️ ~1s normal, spikes under load (monitor via metrics)
Recovery ✅ Automatic restart on failure (configured in transform)

Mitigation: Prometheus alerting on transform state/lag + comprehensive metrics

⚡ Reliability Answer: Both are reliable with proper monitoring. MODE 1 has stronger consistency (ACID), MODE 2 has better observability (metrics).
