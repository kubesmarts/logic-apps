Capacity & Tuning: Reliability

Can we trust PostgreSQL triggers and Elasticsearch transforms?

MODE 1: PostgreSQL Triggers

Aspect Analysis
Atomicity ✅ ACID transaction
Failure Modes ❌ Trigger error = rollback
Monitoring ⚠️ Custom metrics needed
Testing ✅ Integration tests
Lag ✅ None (< 1ms)
Recovery ✅ FluentBit retry

Mitigation: Integration tests + schema validation

MODE 2: Elasticsearch Transforms

Aspect Analysis
Atomicity ⚠️ Eventual consistency
Failure Modes ✅ Auto retry (backoff)
Monitoring ✅ Stats API + Prometheus
Testing ✅ Integration tests (2s wait)
Lag ⚠️ ~1s (spikes under load)
Recovery ✅ Auto restart

Mitigation: Prometheus alerting + metrics

⚡ Reliability Answer: Both are reliable with proper monitoring. MODE 1 has stronger consistency (ACID), MODE 2 has better observability (metrics).
