Capacity & Tuning: Log Replay

Can we replay old logs from /var/log/kubernetes?

Replay Mechanism:

  • Log retention: Kubernetes keeps logs in /var/log/containers/ (configurable, typically 7-30 days)
  • FluentBit restart: Re-reads logs from beginning if position DB lost
  • Manual replay: Stop FluentBit, delete position DB, restart
  • Selective replay: Use kubectl cp to extract specific log files and re-inject

Idempotency Guarantees:

  • MODE 1: UPSERT ensures duplicate events update same row (COALESCE preserves first/last values correctly)
  • MODE 2: Transform aggregates by workflow ID (duplicate events collapsed into single document)
  • No data corruption: Out-of-order or duplicate events handled correctly
  • Safe replay: Can re-process entire log history without side effects

✅ Replay Answer: Yes, idempotent design allows safe replay of old logs. UPSERT (MODE 1) and aggregation (MODE 2) prevent duplicates.
