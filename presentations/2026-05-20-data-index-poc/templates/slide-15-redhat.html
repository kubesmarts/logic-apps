Red Hat Productization Strategy

FluentBit vs Fluentd (EFK Stack)

Aspect FluentBit (Current) Fluentd (Red Hat EFK)
Performance ✅ Lightweight (450KB), low memory ⚠️ Heavier (Ruby VM, ~40MB)
Red Hat Support ❌ Not officially supported ✅ Supported via EFK stack
Elasticsearch Integration ✅ Direct output plugin ✅ Native EFK integration
PostgreSQL Support ✅ pgsql output plugin ✅ fluent-plugin-pgjson
Configuration Complexity ✅ Simpler (YAML config) ⚠️ More complex (Ruby DSL)
Existing Logging Integration ❌ Separate deployment ✅ Leverage existing EFK logs
Migration Effort N/A (current) ⚠️ Reconfigure DaemonSet + config

💡 Recommendation: Start with FluentBit (lighter, simpler). Migrate to Fluentd only if enterprise support or EFK integration required.

🎯 Red Hat EFK Benefit: Single logging pipeline for ALL cluster logs (not just workflow events). Data Index becomes a consumer of existing EFK infrastructure.
