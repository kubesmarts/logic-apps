Architectural Decision Framework

Which mode is right for your use case?

Choose MODE 1 if:

  • ✅ Workflow volume < 50K/day
  • ✅ Strong consistency required (ACID)
  • ✅ Existing PostgreSQL expertise
  • ✅ Simpler operations preferred
  • ✅ Real-time queries critical (< 1ms lag)
  • ✅ Standard relational queries sufficient
  • ✅ Minimal infrastructure footprint

💡 Best for: Traditional enterprise deployments, smaller scale, PostgreSQL-centric stacks

Choose MODE 2 if:

  • ✅ Workflow volume > 50K/day
  • ✅ Eventual consistency acceptable
  • ✅ Full-text search needed
  • ✅ Complex aggregations required
  • ✅ Existing Elasticsearch/EFK stack
  • ✅ Multi-tenancy (index-per-tenant)
  • ✅ Horizontal scaling critical

💡 Best for: Cloud-native deployments, large scale, Elasticsearch-centric stacks, SaaS platforms

Key Decision Factors:

Factor MODE 1 MODE 2 Notes
Scale Threshold < 50K/day > 50K/day Primary decision point
Consistency Strong Eventual ACID vs BASE trade-off
Operational Complexity Low High ES cluster vs single DB
Migration Path Seamless (same GraphQL API) Can switch later if needed
